## Log
- 2026-11-23 (assistant, computer use): Store 1.3.0 package uninstalled by the user so the NSIS install could be driven. Steps 13, 16, 17, 20 (by hand), 21 (local half) run. **Bug found: `--silently` launch stays on the loader until the window is focused** (step 20) — fix before shipping 1.3.1.
- 2026-11-23 observation, not yet a finding: Protocols → **Launch on startup** shows **Off** while the synced account config has `autostartEnabled: true`. Check which one the toggle reflects (registry Run entry on this PC vs account flag) and whether the NSIS install has a Run entry at all.
- 2026-11-23 **step 20 `--silently` root cause** (assistant): `main.tsx` sets `html[data-unfocused]` whenever the window lacks focus, and `tokens.css` then pauses every CSS animation. The loader's finish is a CSS fade (`li-fade`), and `loader.js` removed the loader only on its `animationend`. A `--silently` launch is shown with `SW_SHOWNOACTIVATE`, so the window is never focused: the fade stayed paused at full opacity over the already-rendered dashboard until a click focused it. The by-hand launch calls `set_focus()`, so it never hit this. Fix (uncommitted): `index.html` keeps `#li-loader.li-done` animations running, and `loader.js` also removes the loader with a 1 s timer. Test `apps/web/src/loader.test.ts`.
- 2026-11-23 **Launch on startup OFF vs account `autostartEnabled: true`** (assistant): not a bug. The switch shows `get_autostart_state` = tauri-plugin-autostart / auto-launch `is_enabled()`: true only if HKCU `…\CurrentVersion\Run` has a `Lock-In` value and `…\Explorer\StartupApproved\Run\Lock-In` is not disabled. On this PC there is **no `Lock-In` value under Run** (only a leftover `StartupApproved\Run\Lock-In = 02…`, i.e. "enabled" in Task Manager terms, which is ignored without the Run value), so OFF is correct for this PC. `autostartEnabled` in the account is only a mirror written after a toggle (last `autostart-set` here: 2026-11-12T07:40:36Z); it never drives the switch. 1.3.2 note: the mirror can go stale (e.g. Run entry removed outside Lock-In); consider not showing/syncing it, or re-mirroring after the read.
- **1.3.2 notes:** (1) the NSIS installer starts Lock-In even with "Run Lock-In" unticked on the Finish page (R2). (2) `SystemUsesLightTheme` reads 0 while Settings → Colors shows Light and the taskbar is white (R3/R4); find where this Windows build stores the taskbar mode and what `tray_state::light_taskbar()` reads. (3) The tray theme is re-read only when the tray is built and at session start/end, so a taskbar theme change while idle leaves the wrong icon set until then; listen for `WM_SETTINGCHANGE` ("ImmersiveColorSet") instead.
