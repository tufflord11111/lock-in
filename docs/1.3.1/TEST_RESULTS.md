- 2026-11-25 **Root cause of the sync wedge (fix 4, `forceWebSockets`).** The RTDB SDK (`@firebase/database` 1.1.x) writes `firebase:previous_websocket_failure = true` to localStorage on every WebSocket open and removes it only after the socket's 2nd data response. A socket opened while signed out sends no auth and no listens, gets no data, and is closed as unhealthy after 30 s, so the flag stays. With the flag set, every later connection starts with JSONP long-polling (`<script src=…/.lp>` in an iframe) to the shard host cached in `firebase:host:<ns>` (`s-…`). Our CSP's `script-src`/`frame-src` allow only the default `synchrofocus-ac0f2-default-rtdb…` host, so the poll never connects and a WebSocket is never tried again. localStorage survives restarts and `goOffline`/`goOnline` + `getIdToken(true)` (why the watchdog did not cure it); a WebView profile reset clears it (why the 23 Nov fresh-profile pass worked). App code never touches `firebase:*` keys; there is one Firebase app and one database instance, created once in `packages/firebase/src/config.ts`; listeners all unsubscribe on uid change. **Fix:** `forceWebSockets()` before `getDatabase()` in `packages/firebase/src/config.ts`: WebSocket only, which `connect-src wss://*.asia-southeast1.firebasedatabase.app` already allows. `script-src` deliberately not widened to `*.asia-southeast1.firebasedatabase.app` (that would allow scripts from any RTDB in the region).
